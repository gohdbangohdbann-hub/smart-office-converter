# Nawa OCR Office

إضافة Microsoft Office لـ **Word وExcel** لتحويل PDF والصور إلى محتوى قابل للتحرير، مع أولوية للغة العربية واتجاه RTL ونظام تحقق ذكي يحدد النتائج التي تحتاج مراجعة قبل الإدراج أو التنزيل.

## ما يقدمه المشروع

تستخدم الإضافة Task Pane واحدة داخل Word وExcel. تدعم مسارات PDF إلى Word، والصورة إلى Word، وPDF إلى Excel، والصورة إلى Excel، إضافة إلى التحويل الذكي. في المتصفح يمكن اختيار الوجهة يدويًا، بينما يحدد Office Host الوجهة تلقائيًا داخل التطبيق. بعد المعالجة يظهر النص أو الجدول، تقرير الثقة، مركز المراجعة، وملف DOCX أو XLSX قابل للتنزيل.

تدعم المعالجة الجماعية الملفات ذات الامتدادات PDF وPNG وJPG وJPEG وTIFF وWEBP. يمكن حفظ ملف مستقل لكل مصدر أو دمج النتائج في Word واحد أو Excel واحد أو إنشاء Worksheet لكل ملف. تُعرض حالات الانتظار والمعالجة والنجاح والمراجعة والفشل والإلغاء مع إعادة المحاولة وفتح آخر نتيجة.

## المعمارية

| الطبقة | المسؤولية |
|---|---|
| `client/` | React 19 وTask Pane وواجهة RTL/LTR ومركز المراجعة والإعدادات والتصدير |
| `shared/` | عقد OCR الموحد، خطط Word وExcel، التحقق، الإعدادات، وحالات الدفعات |
| `server/` | tRPC، التحقق من الملفات، preprocessing، مزود Demo المحلي ومزود Azure Layout |
| `manifest.xml` | تعريف Office Add-in وموارد Word وExcel وعنوان HTTPS للمعاينة |

محرك OCR يختار `demo-local` عند غياب إعدادات Azure، أو `azure-document-intelligence-layout` عند وجود endpoint وkey. لا توجد مفاتيح Azure في الواجهة، ولا تُحفظ bytes الأصلية بعد اكتمال المسار الخادمي.

## المتطلبات والتثبيت

يتطلب المشروع Node.js 22 أو أحدث وpnpm. من مجلد المشروع:

```bash
pnpm install
```

## التشغيل والفحص

```bash
pnpm dev
pnpm check
pnpm test
pnpm build
```

يعمل الوضع المحلي دون مفاتيح Azure باستخدام Demo provider. لتشغيل Azure خارج نطاق local-only، تُضبط الأسرار في بيئة الخادم فقط عبر إعدادات المنصة، مع `OCR_PROVIDER=azure` و`AZURE_DOCUMENT_INTELLIGENCE_ENDPOINT` و`AZURE_DOCUMENT_INTELLIGENCE_KEY`.

## Word وExcel

في Word، تُبنى الفقرات والعناوين والقوائم والجداول مع اتجاه RTL/LTR وترتيب قراءة متعدد الأعمدة محافظ، ثم يمكن إدراجها عبر `Word.run`. في Excel، تُبنى الخلايا والصفوف والأعمدة وWorksheet والجداول مع تصنيف النص والرقم والتاريخ والنسبة والعملة، وحماية الأصفار الافتتاحية، والدمج المؤكد، ثم يمكن الإدراج عبر `Excel.run`.

يمكن تشغيل المعاينة دون Office desktop، لكن اختبار sideload وإعادة فتح الملفات داخل Word وExcel المكتبيين يحتاج بيئة Office فعلية ولم يُدّعَ تنفيذه هنا.

## الإعدادات والخصوصية

تُحفظ اللغة، لغة OCR، شكل الأرقام، إعدادات Word وExcel، وخيارات التحويل في `localStorage` بمفتاح إصدار. القيمة الداخلية للخلايا لا تُحوّل بسبب طريقة العرض؛ تغيير شكل الأرقام يؤثر على العرض والتصدير فقط وفق الإعداد. حد الإدخال المحلي الحالي هو 12 MiB، مع رسائل واضحة للملفات الفارغة أو التالفة أو غير المدعومة.

السجلات التشخيصية تسجل النوع والحجم وعدد الصفحات والمدة والحالة ونوع الخطأ فقط. لا تسجل النص الكامل أو محتوى المستندات.

## الاختبارات والنتائج

تغطي Vitest عقد OCR، preprocessing، Word، Excel، RTL/LTR، المراجعة الذكية، التفضيلات، أسماء الملفات، الدفعات، الملفات التالفة، وحد الحجم، إضافة إلى benchmark هندسي محلي لعينات 1 و10 و50 صفحة. عدد الاختبارات الفعلي ونتائج آخر تشغيل موثقان في `PHASE-5-REPORT.md`.

لا توجد نسب دقة OCR في المشروع؛ دقة Character أو Word أو Cell أو Row/Column تحتاج ملفات عربية مرجعية وground truth. قائمة الحالات المطلوبة وطريقة القياس موجودة في `FINAL-ARABIC-BENCHMARK.md` دون أرقام مصطنعة.

## الحدود التقنية

المزود المحلي Demo إرشادي وليس مقياسًا لجودة OCR الإنتاجية. مسار Azure Layout مشروط بأسرار خارجية. استخراج الصور الثنائية داخل Word، والتحقق المكتبي الحقيقي، ودقة benchmark العربية، واختبار PDF كبير فعليًا، كلها تحتاج ملفات وبيئات خارجية. لا تُقدم الواجهة أو التقارير وعدًا بـ 100% دقة أو صفر أخطاء.

## الملفات المهمة

`PHASE-4-REPORT.md` يوثق مركز المراجعة السابق، و`PHASE-5-REPORT.md` يوثق تسليم الدمج النهائي والاستقرار، و`FINAL-ARABIC-BENCHMARK.md` يسجل ما يحتاج إلى ground truth حقيقي. ملف `todo.md` يحتفظ بتاريخ البنود وحالتها.

## معاينة المخرجات قبل التنزيل

بعد اكتمال التحويل، يظهر قسم **معاينة ملف DOCX/XLSX** داخل منطقة النتائج. تعرض معاينة Word الصفحات والفقرات والعناوين والجداول مع اتجاه RTL/LTR، بينما تعرض معاينة Excel الأوراق والجداول والخلايا والقيم الرقمية. تعتمد المعاينة على نفس `WordDocumentPlan` و`ExcelWorkbookPlan` اللذين يستخدمهما التصدير، لذلك يمكن للمستخدم مراجعة المحتوى قبل الضغط على زر التنزيل. لا تُنشأ ملفات دائمة للمعاينة ولا يتغير الملف الأصلي.
